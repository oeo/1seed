# Audit: 1seed

## Verdict

Overall maturity: prototype (macOS file-backed seed only; every OS credential
store is unverified)

Release decision: blocked

## Findings

```text
h1  Cargo.toml:51, README.md:46, src/cli.rs:29  high: on Linux the "keyring" is kernel keyutils, which keyring 3.6.3 documents as in-memory and lost on reboot; docs and help claim Secret Service. `init --generate` reports "seed stored in keyring", then the seed vanishes with no backup. Use a persistent Secret Service backend or file storage on Linux, and correct the claim.
h2  src/seed.rs:37  high: release binaries honor ONESEED_TEST_MODE, dropping scrypt from N=2^20 to 2^12 and silently changing every key for the same passphrase. Gate the weak parameters to test builds only.
h3  src/seed.rs:55, src/seed.rs:67  high: seed decoding content-sniffs and accepts malformed input. A text passphrase of 32+ bytes with a trailing newline is used as raw first-32-bytes with no scrypt; a 1SED2 seed with one appended byte yields different keys at exit 0; an empty file yields keys from scrypt(""). Reject empty input and magic-prefixed wrong lengths; make the legacy path explicit.
m1  tests/integration.rs:39, src/seed.rs:37  medium: no known-answer vectors, every test runs N=2^12, and no test touches a keyring backend, so a silent derivation change passes CI. Add fixed vectors per key type at production parameters.
m2  src/seed.rs:180, src/derive.rs:32, src/password.rs:26  medium: HKDF info omits output length and does not escape `/`. The 12-word mnemonic shares 11 words with the 24-word one, and realm `a` `derive raw ssh` equals realm `a/raw`'s SSH private seed. Bind length and encode components under a new derivation version.
m3  src/password.rs:79  medium: the class fix-up can overwrite the only character of an earlier class. Passwords missing a class: 641/1500 at length 4, 93/2000 at 8, 1/2000 at 16. Pick non-colliding positions, under a new version.
m4  src/seed.rs:99, src/seed.rs:132, src/seed.rs:143  medium: any keyring error is swallowed. Load falls through to ~/.1seed, init can create a second seed when the keyring is unreachable, and forget reports "seed removed" when the keyring delete failed. Separate "no entry" from backend failure.
m5  .github/workflows/ci.yml:83, .github/workflows/ci.yml:130, Makefile:79  medium: release does not depend on the audit job, builds without --locked, ships unsigned artifacts with no checksums, and `make release` pushes without running checks. Cargo.toml is 0.8.0 but the latest tag is v0.7.0.
m6  src/seed.rs:219, README.md:46  medium: off unix the fallback seed file is a plain std::fs::write with no ACL, while the README claims mode 0600. Restrict the ACL or narrow the claim.
m7  src/cli.rs:370, src/cli.rs:382  medium: `sign data -o` writes base64 but `sign verify @file` reads raw bytes, so the tool rejects its own signature file ("invalid signature length"). Decode base64 from @file or default -o to binary.
l1  src/age.rs:131  low: `age decrypt -k` rejects age-keygen files with comment lines ("invalid Bech32 encoding"). Parse with age's IdentityFile.
l2  man/1seed.1:3, completions/1seed.bash  low: man page says 0.7.0 and neither it nor the completions know --seed-file. Regenerate and add a CI drift check.
l3  src/cli.rs:478, src/seed.rs:162, src/cli.rs:546, src/cli.rs:558  low: init and forget ignore --seed-file; SEED_FILE pointing at a missing file makes init fail "seed already exists"; status labels --seed-file as SEED_FILE and --realm as SEED_REALM.
l4  README.md:95, src/age.rs:22, src/cli.rs:506  low: "derived keys are zeroized" does not hold for identity strings, SSH private key text, prompted passphrases, or the master copy in init. Wrap them in Zeroizing or narrow the claim.
l5  src/sign.rs:50  low: verify uses non-strict Ed25519 verification, which accepts small-order keys. Use verify_strict.
```

## Required Gates

1. Linux: a seed stored by `init` survives reboot, shown on a Linux host.
2. A release build ignores `ONESEED_TEST_MODE`.
3. Malformed seed input (empty, `1SED2` with wrong length, ambiguous legacy
   text) fails with an error.
4. Known-answer vectors for age, SSH, sign, password, mnemonic, raw, int, and
   uuid at N=2^20.
5. Keyring store, load, and forget executed on macOS, Linux, and Windows.
6. Release job depends on audit, builds `--locked`, publishes checksums, and
   the tag matches the Cargo version.
